## 로컬 개선 기록 · 2026-09-06

아래는 운영 복구 전 로컬 개선 기록이다. 현재 배포 결과는 문서 상단, 재실행 명령은 [커밋 전 검증](#3-커밋-전-검증)을 따른다.

- 방향 검토: correctness와 failure modes에서는 브라우저의 재시도·후속 조회 실패가 저장 상태를 잘못 표현하는 문제가 확인됐다. architecture·maintainability·불필요한 복잡성 관점에서는 검증된 API/DB 계약을 유지하는 국소 수정이 적합하다. 요구사항과의 일치 여부는 게스트 → 메뉴 선택 → 계정 저장 흐름으로 판단한다. 전체 재작성은 필요하지 않다.
- 메뉴 선택 게이트: 실제 서버가 201로 저장한 응답만 브라우저에서 유실시킨 뒤, 같은 요청으로 200 replay와 내역 1개를 확인한다. 재시도마다 새 요청 키를 만들지 않는다. 카드 수명 안에서 키를 유지하며 새로고침 후 재시도 복구까지 보장하지 않는다.
- 저장 결과와 읽기 결과는 별개다. 후속 내역 조회의 503을 저장 실패로 표시하거나 저장 버튼을 다시 활성화하지 않는다. 두 실패 시나리오 모두 수정 전 실패를 재현했고, 수정 후 360/390px 브라우저 4개 검사가 통과했다(2026-09-06).
- 테스트 교훈: 요청 유실 주입은 서비스 워커를 차단한 브라우저에서 수행한다. 서버 저장을 모의 성공으로 대체하지 않는다. OneDrive 내부 trace 파일 잠금이 발생하면 테스트 산출물만 임시 디렉터리로 옮긴다.
- 게스트 가져오기: 기존 계정 로그인은 자동 병합하지 않는다. 내 정보에서 명시적으로 가져온 뒤 재료·선택 내역을 즉시 갱신한다. 등록 시 병합과 부분 실패 재시도는 같은 요청 키를 사용한다. 로그아웃·계정 전환 후 이전 요청의 결과로 화면을 갱신하지 않는다.

- 검토 결정: 기존 구조를 유지하고 국소 수정한다. `shower`의 후속 조회 실패·로그아웃 경합 finding을 반영했다. `ssotize` 읽기 전용 감사에서는 기존 API/DB 계약과 충돌하거나 새로 통합해야 할 사실이 없었다. 검증은 실제 저장 후 브라우저 실패를 주입하며, 로컬 결과를 운영 증거로 간주하지 않는다. 외부 사실·이식성 주장이 없어 해당 사실 확인·이식성 정리는 생략했다.

## 복구 전 보안·연결 점검 · 2026-09-08

Understood as: 기존 작업과 데이터를 보존하면서 지정 Supabase·Vercel 프로젝트의 연결과 SQL 보안을 점검하고 필요한 최소 수정으로 앱을 정상 작동시킨다. 전체 초기화는 필요성이 입증되지 않아 하지 않는다.

- 운영 `/health`는 HTTP 200, `supabaseDatabaseConfigured=true`, `localDbConfigured=false`다. `groqConfigured=true`로, 문서의 Groq 제외 설정과 차이가 있다. 이번 점검은 Groq 호출·설정 변경을 수행하지 않았다.
- `/api/auth/session`은 200이나 `POST /api/guest/session`은 503 `DATABASE_UNAVAILABLE`다. 요청 ID는 `7ff881d5-437c-41b1-afbc-2d4fa5ac4a8f`. 테스트 재료 생성 전 실패해 운영 저장·재조회는 미완료다. 공개 응답만으로 SQL 누락·권한·정리 함수 오류 중 하나를 확정하지 않는다.
- 로컬 SQL에서 격리 테이블 RLS 누락, 역할별 명시적 RPC 권한 잔존 가능성, 병합 이력이 있는 만료 세션 정리의 외래키 실패를 확인했다. 후속 마이그레이션은 데이터를 초기화하지 않고 권한과 함수만 변경한다. 병합은 동일 게스트 단위로 직렬화하고 정리와 행 잠금을 공유한다. 독립 cold-read의 경합 지적을 반영했다.
- 중복 가입 충돌의 SQLSTATE `23505`만 서버 내부에서 보존해 409로 처리한다. 외부 SQL 오류 본문·개인정보는 응답이나 로그로 전달하지 않는다.
- 로컬 검증: DB·스키마 25개, SQL 실행 2개, API·배포 24개, PWA 5개, 모바일 브라우저 22개 통과. API 전체 첫 실행에서 배포 본문 검사 연결 실패 1건이 있었으며 단독 재현과 최종 전체 재실행은 통과했다. JS 구문과 diff 공백 검사 통과. 이 결과는 실제 운영 복구 완료를 의미하지 않는다.
- SQL 검사 독립성: 문자열 패턴 검사만으로 보안을 판단하지 않고 PostgreSQL 엔진의 권한 오류·외래키 오류·실제 행 수를 검사한다. PGlite는 다중 접속 경합이나 운영 PostgREST를 검증하지 않는다. 신규 스키마와 후속 수정의 중복은 배포 스냅샷 구조이며 일치 검사를 추가했다. 기존 마이그레이션은 수정하지 않았다.
- `supabase init` 완료. 프로젝트 link는 계정 인증이 없어 미완료. Vercel Connect 호출은 로컬 프로젝트 OIDC 누락으로 실패했으며 CLI도 로그아웃 상태였다. 로그인 절차를 시작했다. 아직 원격 SQL 적용, 운영 환경 수정, 배포는 하지 않았다.
- 다음 필수 작업: 계정 인증 후 지정 프로젝트의 실제 스키마·권한·마이그레이션 이력과 Vercel 오류 로그를 확인하고 미적용 수정만 적용한다. 이어 게스트 저장·추천·선택·회원가입·로그인·병합을 운영에서 검증한다. 상세 적용 절차는 [배포 설정](deployment.md)을 따른다.
